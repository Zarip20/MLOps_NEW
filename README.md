# MLOps-система обработки потоковых табличных данных

Бинарная классификация полисов страховой компании по признаку
`CLAIM_PAID` (произошёл ли страховой случай). Учебный набор данных
Ethiopian Insurance Corporation: 508 499 строк, 16 колонок, июль 2014 —
июнь 2018, помесячные батчи (48 штук).

Полное описание задачи и ход работы — в папке [`doc`](doc/) и в
[`PLAN.md`](PLAN.md).

---

## Быстрый старт

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-lock.txt pytest

.\.venv\Scripts\python run.py -mode init          # разбить источник на батчи
.\.venv\Scripts\python run.py -mode update -n 12  # обучить на 12 батчах
.\.venv\Scripts\python run.py -mode summary       # отчёт и дашборд
```

Требуется Python 3.13. Полный прогон всех 48 батчей занимает около
15 минут и 2 ГБ оперативной памяти.

## Команды

| Команда | Что делает |
|---|---|
| `run.py -mode init` | Распаковывает источники, режет на батчи, сохраняет сборщик данных |
| `run.py -mode init -reset` | То же с полным сбросом обучения |
| `run.py -mode update [-n N]` | Дообучает модели на очередных батчах |
| `run.py -mode sync` | Добавляет в состояние батчи, принятые сборщиком извне |
| `run.py -mode inference -file F` | Прогноз с проверкой входа и калибровкой порога |
| `run.py -mode summary` | Анализ Meta Learning, текстовый отчёт, HTML-дашборд |
| `run.py -mode publish` | Собирает статический сайт с дашбордом для GitHub Pages |
| `python -m src.collector --describe` | Сводка по каталогу батчей |
| `python -m src.collector --append F` | Принять новый батч из внешнего файла |
| `python -m src.publish --out DIR` | Собрать сайт (то же, что `-mode publish`) |
| `pytest tests -q` | 302 теста |
| `python -m tests.check_workflow .github/workflows/main.yml` | Проверить workflow |

### Приём данных извне

```powershell
python -m src.collector --append data/new_month.csv
python run.py -mode update -n 1
```

Сборщик проверяет схему, разбирает даты, приводит их к единому виду и
отказывается принимать файл за уже известный месяц. Он же сериализуется
в `models/collector.pkl` — этот артефакт можно взять из прогона CI и
принять новые батчи, не имея исходных данных.

## Что делает конвейер

На каждый батч последовательно:

1. **Качество данных** — полнота, валидность, уникальность, статические
   и ассоциативные правила, своевременность, EDA.
2. **Очистка** — нормализация категорий (`Truck`/`truck`), числовые
   сентинелы, дубликаты.
3. **Дрейф** — PSI и KS по числовым признакам, отдельно — дрейф метки.
4. **Признаки** — 12 инженерных признаков поверх исходных колонок.
5. **Обучение** — четыре модели: `lr`, `dt`, `rf`, `mlp`; сравнение на
   hold-out по f1. `mlp` дообучается через `partial_fit`.
6. **Гейт качества** — новая версия становится продуктовой только если
   проходит пороги и не хуже текущей.
7. **Реестр** — все версии с метриками; файлы старых версий
   ограничены по числу, записи остаются все.
8. **Интерпретация** — важность признаков, для дерева — пути решения.
9. **Накопление** — обучающая часть складывается в растущее хранилище.
10. **Перебор предобработки** — на первом батче, выбор варианта по f1.
11. **Метаданные** — манифест батча со всем перечисленным.

Метрики: precision, recall, f1, roc_auc. Продуктовая модель выбирается
по f1, но не автоматически: решение проходит гейт.

При инференсе вход проверяется, а решения принимаются по
**калиброванному порогу** — это нужно, потому что модели завышают долю
положительного класса в 5–10 раз. Подробно — в [`doc/task.md`](doc/task.md) §9.

## CI/CD

Workflow **MLOps CI Pipeline** (`.github/workflows/main.yml`): три job
`test → train → publish`, запуск по push, pull request, расписанию и
вручную. Артефакты: логи, отчёты, модели, метаданные, дашборд и сайт.
Дашборд разворачивается на GitHub Pages.

Инструкция по запуску CI: [`doc/github_actions.md`](doc/github_actions.md).
Что система умеет и чего не умеет: [`doc/task.md`](doc/task.md) §9.
Презентация для защиты: [`doc/presentation.md`](doc/presentation.md).

## Структура

```
.
├── config.yaml                  # единственный источник настроек
├── requirements.txt             # прямые зависимости
├── requirements-lock.txt        # полный зафиксированный состав
├── run.py                       # точка входа, только разбор аргументов
├── scripts/run_pipeline.sh      # единый скрипт для локали и CI
├── src/
│   ├── pipeline.py              # оркестратор этапов
│   ├── config.py                # загрузка и валидация конфигурации
│   ├── collector.py             # сериализуемый сборщик данных
│   ├── data_collection.py       # источник, батчи, хэш набора
│   ├── storage.py               # накопительное хранилище обучающей части
│   ├── data_quality.py          # метрики качества и очистка
│   ├── rules.py                 # декларативные правила качества
│   ├── association.py           # ассоциативные правила (Apriori)
│   ├── features.py              # инженерные признаки
│   ├── preprocessing.py         # ColumnTransformer
│   ├── training.py              # обучение и дообучение
│   ├── registry.py              # версии моделей и гейт качества
│   ├── drift.py                 # PSI и KS
│   ├── explain.py               # интерпретация моделей
│   ├── report.py                # текстовый отчёт
│   ├── dashboard.py             # HTML-дашборд истории обучения
│   ├── publish.py               # сборка сайта для GitHub Pages
│   ├── ports.py                 # порт представления (7.b.iv)
│   ├── views.py                 # представления: анализ, отчёт, дашборд, сайт
│   ├── meta.py                  # Meta Learning: влияние настроек, динамика
│   ├── inference.py             # проверка входа, калибровка, деградация
│   ├── preprocessing_sweep.py   # перебор вариантов предобработки (3.b.i)
│   ├── state.py                 # версионированное состояние прогона
│   ├── logging_setup.py         # единое логирование в файл и консоль
│   └── utils.py                 # утилиты: JSON, pickle, даты, память
├── tests/                       # 302 теста
├── data/                        # батчи, метаданные, правила (генерируются)
├── models/                      # модели, препроцессор, сборщик (генерируются)
├── reports/                     # отчёты и дашборд (генерируются)
├── site/                        # собранный сайт (генерируется)
└── doc/                         # задание, оценка, отчёт, инструкции, защита
```

Каталоги `data/`, `models/`, `reports/`, `site/` создаются прогоном и не
хранятся в git. Единственный файл с данными в репозитории —
`data/motor_data14-2018.zip` (6,4 МБ); распакованный CSV и батчи
исключены.

## Данные

- `INSURED_VALUE == 0` — значимое значение (45,5 % строк), а не пропуск.
- `CARRYING_CAPACITY` — 23 % пропусков, у грузовых транспортных средств
  это нарушение правила качества, а не дефект разметки.
- `EFFECTIVE_YR` — 640 испорченных значений.
- Доля страховых случаев падает с 7,43 % до 2,4 % (−78,7 % за четыре
  года). Это тренд целевой метки, а не аномалия; он отслеживается
  отдельно от PSI по признакам.

Пороги дрейфа и качества выбраны по результатам профилирования всех
48 батчей; обоснования — в [`PLAN.md`](PLAN.md), §1.2 и §1.8.
